## 2. 需要在 AGC 完成的事

### 2.1 创建应用
1. 登录 AGC →「我的应用」→ 新建应用 → 选择 **HarmonyOS**。
2. 填写包名 `com.kwin.photocraft`（当前工程值）、应用名 `ArtsPhoto`、分类（工具 > 图片编辑）、设备（手机 / 平板 / 2in1）。
   - 包名一旦在 AGC 创建即不可改。若希望包名也改为 `com.kwin.artsphoto`，请在创建前先告诉我改工程包名，并重新申请 Profile。
3. 创建后取得 APP ID。

### 2.2 发布证书与 Profile（已完成）
1. **已复用**：Notepad 的 `.p12`、`.cer`、`keyAlias=qingjian_notepad` 与密码已写入本工程 `build-profile.json5` 的 `release` signingConfig。
2. **Profile 已就位**：`docs/launch/artsphotoRelease.p7b`，解析结果 `bundle-name=com.kwin.photocraft`、`type=release`，已配置到 `release.material.profile`。
3. 构建脚本会读取 `.p7b` 的 `bundle-name` 与 `AppScope/app.json5` 对比，不一致时拒绝生成上架包（已实测通过）。
4. 仓库中的调试签名与 `release` 证书绝对路径属于本机配置，**不要提交**。

### 2.3 备案
ArtsPhoto 无网络权限，属于单机应用：在 AGC 备案信息处勾选「您的 APP 为单机 APP」，无需备案号。将来若加入联网 / 账号 / 统计，必须先备案。

### 2.4 隐私政策与用户协议
- 将 `docs/launch/隐私政策.md` 托管到可公开访问的 HTTPS 页面，把 URL 填到 AGC「隐私政策」。
- 应用内已有同一份文本（`LegalPage.ets`），两侧必须保持一致。
- 替换文档与代码中的开发者全称、联系邮箱：
  - `docs/launch/隐私政策.md`、`docs/launch/用户协议.md`
  - `entry/src/main/ets/pages/LegalPage.ets` 的 `DEVELOPER_NAME` / `CONTACT_EMAIL`

### 2.5 应用信息
| 材料 | 要求 |
|---|---|
| 应用图标 | `docs/launch/app-icon-1024.png`（1024×1024）、`app-icon-216.png`（216×216） |
| 应用截图 | 横屏 1920×1080 与竖屏 1080×1920 **各 3~10 张**，见 `docs/launch/截图清单.md` |
| 应用介绍 | 见 `docs/launch/应用介绍与一句话简介.md` |

### 2.6 提交与发布
1. 上传 `.app` → 选择版本 → 填应用信息 → 提交审核。
2. 常规审核约 1~3 个工作日，多数 24 小时。
3. 被打回过建议在「互动中心」申请加急并附整改说明。

## 3. 构建发布包

```powershell
# 配置好发布证书后
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-photocraft.ps1 -PackageType app
```

- 脚本自动追加 `-p buildMode=release`，使用 `release` product 与发布签名，并拒绝 `debugKey` 调试签名。
- 产物：`build/outputs/release/photocraft-release-signed.app`。
- 本地仅验证链路可加 `-AllowDebugSigning`，该产物**不能提交审核**。

产物自检：

```powershell
python -c "import zipfile,io,json; a=zipfile.ZipFile(r'build/outputs/release/photocraft-release-signed.app'); h=zipfile.ZipFile(io.BytesIO(a.read('entry-default.hap'))); m=json.loads(h.read('module.json')); print(m['app']['debug'], m['app']['buildMode'], m['app']['vendor'])"
```

应为 `False release Kwin`。

## 4. 图标一致性（Notepad 实际驳回点）

Notepad 第 4 版因「AGC 上传图标 ≠ 安装后桌面图标」被驳回。ArtsPhoto 已按同样口径处理：

- 桌面图标：`module.json5 → abilities[0].icon → $media:layered_image`（前景 + 背景分层）。
- 启动窗口图标：`$media:app_icon`（1024 合成图，与桌面图标同美术）。
- `AppScope` 与 `entry` 两份 `foreground.png` / `background.png` 已字节统一，避免编译期覆盖分叉。
- AGC 上传素材 `docs/launch/app-icon-1024.png` 与包内 `resources/base/media/app_icon.png` **sha256 相同**（当前 `698fe1490eb08a1d…`）。
- 图标美术：深蓝渐变底 + 三层照片卡片 + 日落山照片 + 青色画笔；前景内容占 68%×57%，已替换旧的 2×2 方块模板图。
- 应用名 `ArtsPhoto` 在三处必须一致：`app_name`、`EntryAbility_label`、AGC「应用名称」。

> 若后续更换图标美术，必须同时更新：AppScope/entry 的 foreground/background、`app_icon.png`、`docs/launch/app-icon-1024.png` / `-216.png`，然后重新构建并重传 AGC。

## 5. 高频驳回原因（照单规避）

1. 未备案或备案信息与包名不一致（本应用勾“单机 APP”）。
2. 图标与安装后不一致、图标非分层 / 尺寸不足（Notepad 1.0.1、1.0.4 实际驳回）。
3. 截图含第三方品牌、其他应用界面、壁纸留白（Notepad 1.0.1 PC 截图驳回）。
4. 隐私政策缺失或首启无同意弹窗。
5. 功能异常 / 崩溃（重点测：大图打开、图层操作、导出、后台切换）。
6. 开关/按钮无反馈（Notepad 1.0.3「自动换行」驳回）。
7. UX 不达标：空状态、错误提示、返回键行为、底部导航条遮挡。
8. 权限申请超出实际用途（本应用无权限，属优势）。

## 6. 版本迭代

- 每次提审必须递增 `versionCode`，并同步 `versionName`：
  - `AppScope/app.json5`（打包进包的权威值）
  - 「关于」页读取的是包内 `versionName`，无需另改常量。
- 建议版本说明写清“本次修复内容 + 审核驳回对应项”。
- 首版建议：`versionCode=1000000`、`versionName=1.0.0`（当前值）。
