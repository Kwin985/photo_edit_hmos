# ArtsPhoto 对比 AirPhoto：SWOT 分析（真机证据版）

> 分析日期：2026-11-19
> 对标对象：AirPhoto（纯血鸿蒙版）`com.airphoto.app` v1.7.0，开发者陈彦霖
> 本作物：`ArtsPhoto`（工程名 photocraft）`com.kwin.photocraft` v1.0.1（versionCode 1000002）
> 证据来源：真机 `bm dump` + 启动截图 + `uitest dumpLayout`（2026-11-19 现场取证）；工程源码与构建产物；`docs/DIFFERENTIATION_CHECKLIST.md` 记录的商城镜像数据（截至 2026-10-27）
> 证据等级：**[已证]** 真机/源码/构建产物直接观测；**[推断]** 基于证据的合理推断；**[未证]** 商城口径但无二进制或运行证据

---

## 一、结论先行

1. **上一轮 SWOT 的两条关键假设被真机证据推翻，必须修正。**
   - V4（AirPhoto 权限）：**已闭合**——AirPhoto 只申请 2 项本地权限（`FILE_ACCESS_PERSIST`、`READ_PASTEBOARD`），**没有 INTERNET 权限，也没有云同步**。所谓"因多端协同推断联网"不成立。本作"不联网"不再是独占卖点，只能升级为"**零权限**"（0 vs 2）的更强但更窄的差异化。
   - V5（生态能力）：**已闭合**——AirPhoto **没有服务卡片、没有 insightIntent**（`formEnabled: false`、无 `formExtensionModule`、`hasIntent: false`）。本作的 1 张卡片 + 2 个意图是**已证实的独占生态位**，应立刻从"待核实优势"升格为主线卖点。

2. **最大威胁被重新识别：AirPhoto 疑似 GIMP 鸿蒙移植。** 真机 `vendor: gnome`、完整 GIMP 式菜单树（文件/编辑/选择/视图/图像/图层/颜色/工具/滤镜/窗口/帮助）、PS 风格新建对话框、97.7 MB 包体、两段式"引擎启动中/正在准备数据文件"冷启动，共同指向 GIMP 血统 **[推断，置信度高]**。若成立，其路径/蒙版/PSD/滤镜纵深大概率远超本作，本作"图层纵深独占"的叙事不成立，须改为"**同等专业能力的触屏化与轻量化**"。

3. **战略重心应调整为：守零权限、抢生态卡位、打触屏体验差；不要与其拼功能清单。** 矢量/抠图等缺口仍是缺口，但"多端协同"缺口的紧迫性显著下降（竞品无公网通道、云同步关闭）。

## 三、SWOT 详表

### S — 优势（内部、正面）

| 编号 | 要点 | 证据与含义 |
|---|---|---|
| S1 | **零权限纯离线** | 本作 0 项权限，竞品 2 项本地权限。二者都不联网，但本作连本地权限也不申请；隐私叙事更干净，且是结构性可验证差异。 |
| S2 | **轻量** | `.app` 28.28 MiB vs 竞品商城标称 97.7 MB（口径不同，但量级差异显著）；本作冷启动无重引擎加载阶段。 |
| S3 | **鸿蒙生态卡位（真机确认独占）** | 服务卡片 + insightIntent 竞品均无。快速新建/最近文档卡片、语音"打开最近编辑"等意图可形成体验差。 |
| S4 | **专业图层能力已落地** | 7 种图层样式、蒙版（密度/羽化/链接）、混合模式、自由变换实时预览、历史跳转、PSD/PSB 打开——均已核实可用。**但不等于独占**（见 T1）。 |
| S5 | **工程质量可交付** | 88 项 hypium + 76 项 Rust 单测 + 真机 arm64 回归 + 发布包验签 PASS；竞品测试情况未知。 |
| S6 | **中文本地化与设备适配** | 内置 NotoSansCJK，真机不缺字；phone/2in1 自适应布局，2in1 最大化。 |
| S7 | **触屏优先的界面** | 底部工具面板、竖屏/宽屏双布局、画布手势直接操作；相比 GIMP 式密集桌面菜单更适合手机（体验层面的相对优势）。 |

### W — 劣势（内部、负面）

| 编号 | 要点 | 证据与含义 |
|---|---|---|
| W1 | **无矢量绘图** | ABI 无 vector 入口，钢笔路径/锚点调节完全空白；竞品商城明确宣称矢量绘图 **[未证但很可能]**（GIMP 血统推断）。单项最大缺口。 |
| W2 | **无 AI 智能抠图** | 仅魔棒阈值选区；竞品宣称智能抠图 **[未证]**。 |
| W3 | **无跨设备协同** | 无分布式能力。**但紧迫性下调**：竞品无公网通道、云同步关闭，其"多端协同"更可能是系统分享/近场文件流转（其 ability skills 支持 `sendData/viewData` 图片，最多 8 张），不是云协同。 |
| W4 | **无 PSD/PSB 导出** | 仅打开；若竞品为 GIMP 移植，PSD 导出大概率具备。格式闭环缺口。 |
| W5 | **商店冷启动** | 0 下载 / 0 评分 vs 8,282 / 4.6；先发劣势是最大客观差距，短期无解，只能靠定位错位缓冲。 |
| W6 | **单人开发 + 上架阻断项** | 隐私政策公网 URL 仍待人工托管；曾有审核驳回记录（分类/开发者名/双弹窗），流程风险仍在。 |
| W7 | **代码混淆关闭** | NAPI 属性名被破坏导致 `a11 is not callable`，为保可用性关闭混淆，代码保护弱于可混淆状态（非隐私风险，属工程债）。 |

### O — 机会（外部、正面）

| 编号 | 要点 | 抓手 |
|---|---|---|
| O1 | **隐私定位重新定义** | 竞品也被证实不联网 → 停止宣称"唯一不联网"，改打"**零权限**：连文件与剪贴板权限都不申请"，并配合 AGC 数据安全勾选"不收集个人信息"。 |
| O2 | **生态独占窗口期** | 竞品无卡片无意图；本作先把卡片/意图做出可感知价值（1→多卡片、语音意图），抢占"鸿蒙原生体验"心智。 |
| O3 | **轻量与流畅心智** | 包体与冷启动差异可做量化对比内容，适合中低端机、折叠屏用户。 |
| O4 | **触屏专业编辑器的体验空档** | GIMP 式桌面菜单在手机上操作成本高；本作的竖屏面板、手势变换、2in1 双栏可作为体验差异化，而非功能差异化。 |
| O5 | **分类与搜索占位** | 拍摄美化 > 图像美化已改报；继续占位"图层编辑器"关键词，避开与竞品全功能对比。 |
| O6 | **迭代节奏窗口** | 竞品最后更新 2026-10-27；本作单人迭代可更快响应（但数据时效需复核）。 |

### T — 威胁（外部、负面）

| 编号 | 要点 | 说明 |
|---|---|---|
| T1 | **竞品疑似 GIMP 鸿蒙移植** | `vendor: gnome` + GIMP 式菜单 + PS 风格新建对话框 + 97.7 MB + 重引擎冷启动 → 功能纵深大概率远超本作已核实范围 **[推断，置信度高]**。本作"图层纵深独占"叙事应废弃。 |
| T2 | **先发势能** | 8,282 下载 / 4.6 分，上架早约 3 个月，搜索排名与评论积累形成壁垒。 |
| T3 | **同类工具与系统编辑器竞争** | 鸿蒙生态内其他图像编辑器及系统级编辑入口，可能同时挤压双方。 |
| T4 | **数据时效** | 竞品数据来自 2026-10-27 镜像，评分/版本可能已变化；V8 未闭合。 |
| T5 | **自我瓦解风险（内部决策外部化）** | 若为补 A2（抠图）引入联网模型、或为补 A3（协同）引入公网通道，将直接摧毁 S1 第一优势。 |
| T6 | **审核与合规** | 分类/[开发者信息/双弹窗曾被驳回；隐私政策 URL 未闭合；任何重提审都有不确定性。 |

## 四、交叉策略

| 策略 | 组合 | 行动 |
|---|---|---|
| **SO（进攻）** | S1+S3+S2 × O1+O2 | 首屏三要素锁定"**零权限 + 鸿蒙卡片/意图 + 更轻**"；商城文案立即从"不联网"改为"零权限"，把真机可验证的 0 vs 2 做成对比图。 |
| **ST（防御）** | S5+S7 × T1+T2 | 不与竞品拼功能清单，改拼**可验证的稳定性与触屏体验**；对 T1 采取"默认竞品有纵深"的保守假设，避免宣传被打脸。 |
| **WO（补课）** | W3+W5 × O4+O6 | 矢量/抠图保留在 1.2.0 之后；先把卡片、意图、触屏体验做成记忆点对抗冷启动；多端协同优先级从 P1 下调（见下）。 |
| **WT（守底线）** | W1+W4+W7 × T5+T6 | 所有补齐项写入硬约束：**不得引入网络权限**（D2 本地模型、D3 近场协同均需回归验证）；保持体积门禁 < 70 MB；尽快闭合隐私政策 URL。 |
